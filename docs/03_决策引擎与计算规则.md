# 决策引擎与计算规则（规范性）

引擎版本 `batch-eval/1.0.0`。本文件优先于页面文案。全部计算是情景估算，不是模型预测。

## 1. 单位、时间与边界

- 金额 `*_fen` 为非负安全整数；贡献和价差允许负值。避免直接用 JS 小数元计算。用户输入人民币最多两位小数，按字符串转整数分，超过两位直接报错，不静默截断。
- 采购数量 `Q`、销量和库存为非负整数，Q>0。第一版整批购买、统一单价 `c`。
- 数量总和、金额乘法与加法均需检查 Number.isSafeInteger；溢出返回 `AMOUNT_OVERFLOW`，不得计算近似结果。
- 内置案例使用 `evaluation_date=2026-11-06`，醒目标注“演示评估日”；新导入批次默认使用浏览器 Asia/Shanghai 当天日期。后续打开示例不随系统时间使金标案例失效。
- 日期为合法 ISO 日期 YYYY-MM-DD，按日期比较而非 UTC 午夜偏移。报价有效至含当天；到货必须早于或等于销售截止日。

## 2. 单一情景公式

每个情景两段销售 `(p1,q1)`、`(p2,q2)`，残值单价 v，其他增量成本总额 K，目标贡献 T：

```
r = Q - q1 - q2
salesRevenue = p1*q1 + p2*q2
residualRecovery = v*r
procurementCost = c*Q
contribution = salesRevenue + residualRecovery - procurementCost - K
contributionRate = contribution / (salesRevenue + residualRecovery)
maxPriceFen = floor((salesRevenue + residualRecovery - K - T) / Q)
breakEvenPriceFen = floor((salesRevenue + residualRecovery - K) / Q)
```

q1+q2>Q 则拒绝计算。r 自动导出，不另设一个可编辑的剩余数量。剩余回收已按净残值计算，不能把相同商品再次计入销售。p1>=p2>=v>=0，任一关系不满足报错。回收额为零时贡献率为 null，展示“—”。

T 与 K 都是整个批次的总额，不是单件。`maxPriceFen` 可为负，不截成 0；负值意味着该情景即使零采购价也不能达到目标贡献。数学结果向下取整至一分钱，不能四舍五入到更高的采购价。

采购预算 `budget_fen` 只约束 `c*Q`，明确不包含 K。另展示 `cashOutlay=c*Q+K`，避免把预算与总支出混淆。阈值：`budgetMaxPrice=floor(budget_fen/Q)`；`safeMaxPrice=min(悲观maxPriceFen,budgetMaxPrice)`。

三情景回收总额须满足 悲观<=基准<=乐观。顺序不一致时要求用户重新命名或调整输入，不自动交换标签。情景只有输入合法且明确确认后才能触发正式建议。

## 3. 推荐规则与优先级

必需信息：完整报价、Q/尺码、三情景、K、T、预算、到货/有效期/销售截止日、至少一条可比引用或“无可比依据”的显式说明、情景依据说明、门店需求代理量和现有库存。

按下面顺序返回第一条命中的主状态，同时保留其他风险列表：

1. 输入非法 → `INVALID`，输入待修正，不生成正式推荐。
2. 缺资料或没有确认 → `NEEDS_DATA`，资料待补。
3. 评估日>报价有效期或到货>销售截止日 → `REJECT`，当前报价不可执行。
4. `safeMaxPrice<0` → `REJECT`，零采购价也无法达标。
5. 当前价>safeMaxPrice，且有底价且底价>safeMaxPrice → `REJECT`，当前已知采购条件不可达标。
6. 当前价>safeMaxPrice，且底价未知或底价<=safeMaxPrice → `NEGOTIATE`，需议价；底价未知标注“议价可行性未核实”。
7. 当前价<=safeMaxPrice，但分店留仓量>0 → `REWORK`，方案待调整，不宣称已可直接采购。
8. 其他 → `BUY`，在已确认情景和约束下可采购。

供应商底价非空时必须 0<=底价<=当前报价；新假设价低于底价时需显式清空或重设底价，不静默修改。不能根据历史推断真实供应商底价。`BUY` 的解释必须说“在当前假设下”，不能说“保证盈利”。

映射默认人工决定：BUY→采购；NEGOTIATE→议价；REJECT→放弃；NEEDS_DATA/REWORK/INVALID→暂缓。人工覆盖需记录理由，不改写系统结果。

## 4. 金标案例

三个批次 Q=1000，K=800000 分，T=2000000 分，预算=10000000 分，三情景均为：

| 情景 | p1（分） | q1 | p2（分） | q2 | v（分） | r | 回收总额（分） |
|---|---:|---:|---:|---:|---:|---:|---:|
| 悲观 |12900|400|7900|350|2000|250|8425000|
| 基准 |12900|600|7900|250|2000|150|10015000|
| 乐观 |12900|750|7900|200|2000|50|11355000|

| 批次 | 当前价（分） | 底价（分） | 悲观贡献（分） | 基准贡献（分） | 乐观贡献（分） | 主建议 |
|---|---:|---:|---:|---:|---:|---|
| LOT-A |5000|4800|2625000|4215000|5555000|BUY|
| LOT-B |6000|5500|1625000|3215000|4555000|NEGOTIATE|
| LOT-C |8000|7500|-375000|1215000|2555000|REJECT|

三个情景达标价分别为 5625/7215/8555 分；预算允许10000分，safeMaxPrice=5625分。这里保持相同收入情景是有意的控制变量，便于展示采购条件变化；不能解释为三个真实商品必然拥有相同需求。LOT-C 另有尺码失配风险，见分店。

LOT-B 假设报价改为5600、底价仍5500：悲观贡献2025000分，基准3615000分，乐观4955000分，建议BUY。改为5625，悲观恰好2000000分，可BUY；5626则悲观1999000分，NEGOTIATE。

预算降至5000000分后预算价上限5000分；LOT-B底价5500分不满足，建议REJECT，原因必须指向预算而非混称商品亏损。

## 5. 历史可比与冷启动

每个历史记录是 date/store/style/size，含units_sold、in_stock。合成样例有84天×5店×4尺码。日期范围包含起止日。

可售日均销量=sum(units_sold)/count(in_stock=true)，仅在数据严格保证缺货日销量为0时使用。可售天数为0返回null；报告缺货天数，不把缺货日作为零需求。不能据此保证还原了真实潜在需求。

可比商品由用户确认；首版只显示类别、季节、价格带、尺码参考以及可售日销量，不自动把其映射成收入预测。新批次没有参考时允许填写“无可比依据”，但必须显式说明假设来源并标注低证据强度。不得生成伪百分比置信度。

## 6. 简版分店算法（确定性启发式）

需求按同类商品组 `demand_group_id` 管理；首版假设该组商品可替代。字段：门店的需求代理量D[店,尺码]、同组现有库存I、新增承接容量cap。D是人工设定的销售窗口参考量，不能称为预测。cap是新增可放件数，不是物理面积。

每个批次独立测算，互相是替代评估，不对库存或门店容量做真实预占。界面显示“未合并其他采购批次”。

算法：

1. 按尺码字典序（S,M,L,XL的明确枚举顺序）处理采购数量。
2. 对激活且勾选门店算 gap=max(0,D-I)，本尺码候选上限=min(gap,cap-已分总量)。
3. 每次在仍有上限的候选中按 `(分配后该尺码库存)/D` 最低优先；D=0不参与；相同比率按store_id升序。
4. 每次分配1件，更新尺码剩余和门店新增容量；没有候选则本尺码全部留仓。
5. 输出 store-size分配、每尺码留仓、门店剩余容量；总分配+总留仓=Q。

比例比较用交叉相乘，避免浮点排序不稳定；Q<=100000且循环总次数最多Q。本算法不含运输费和仓网最优性。

样例五店各cap=240，四尺码D=[30,60,90,120]，I=[10,20,30,40]。LOT-A/B采购尺码=[100,200,300,400]，每店分=[20,40,60,80]，合计每店200、总1000、留仓0。LOT-C=[700,100,100,100]，每店分=[20,20,20,20]，总400，S留仓600。C优先返回财务REJECT，同时展示留仓风险。

## 7. 快照及复盘

保存快照复制完整输入、证据摘要、结果、分配与版本，不仅保存对象ID。建议更改、模型输出刷新、seed重置均不得回写快照。快照包含输入指纹 input_hash 与输出指纹 result_hash，JSON按键排序后SHA-256，字符串UTF-8；对象键递归字典序排序，数组维持规范顺序，JSON紧凑无额外空白。规范输入对象的完整字段见04，时间戳、AI文本、工作进度status与所有hash字段（包括confirmed_for_hash）不进入输入指纹。状态确认基于输入指纹；计算输入改变后confirmed_for_hash失配，正式推荐回到NEEDS_DATA。

复盘仅针对已采购快照、完整销售窗口与数量守恒的实际结果，review_date必须不早于快照selling_end_date。内置演示使用未来模拟期末日期并标注，不能称为真实已实现收益。实际采购成本使用实际总额；其他成本用实际总额；售价/销量和残值同公式。实际贡献=实际销售收入+实际净残值-实际采购成本-实际其他成本。

差异桥接：收入差=实际销售-基准销售；残值差=实际残值-基准残值；采购成本影响=基准采购成本-实际采购成本；其他成本影响=基准其他成本-实际其他成本。四项之和=实际贡献-基准贡献。

内置复盘只在用户把LOT-B报价改到5600并保存“采购”后可载入：实际两段销量550/300，售价12900/7900分，残余150件×2000分，采购总成本5600000分，其他成本900000分。实际贡献3265000分，相对该快照基准3615000分减少350000分；桥接=-250000+0+0-100000分。
