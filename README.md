# 品牌尾货采购决策工作台

给服饰折扣零售买手使用的采购评估 Demo。供应商拿来一批数量和尺码固定的尾货时，买手可以核对报价、比较销售情景、反推最高进货价，再检查门店能否承接。系统保存人工决定和当时的假设，供销售结束后复盘。

## 快速开始

需要 Node.js 20 或以上版本。核心流程无需配置模型 API Key。

```bash
npm ci
npm run dev
```

在浏览器打开 [http://localhost:3000](http://localhost:3000)。内置品牌、供应商、门店和经营数据均为合成示例。

## 五分钟演示

1. 首页打开 **云杉运动卫衣（LOT-B）**，看一批 1,000 件、每件 60 元的报价。
2. 进入 **情景测算**。核对悲观、基准、乐观三组销售假设，再点 **确认情景**。60 元时悲观贡献为 16,250 元，低于 20,000 元的目标，系统建议议价。按这组假设，最高进货价为 **56.25 元**。
3. 把报价改成 **56 元**并重新确认。悲观贡献变为 **20,250 元**，只比目标多 250 元。把悲观情景的首段销量临时由 400 改成 390，可看到目标余量转负。测试完请恢复到 400 并再次确认。
4. 打开 **门店分配**。按尺码需求、同类现有库存和门店容量分配，五家示例店共能承接 1,000 件。取消一家店可看到 200 件留仓。保存前恢复选店并重新确认。
5. 回详情页保存 **采购** 决策。在只读快照里载入模拟期末结果。模拟实际贡献 32,650 元，较基准少 3,500 元，其中销售收入少 2,500 元，其他成本多 1,000 元。

## 产品规则

- 情景贡献等于销售收入加剩货净回收，再扣进货费和其他增量成本。买手设定目标与销售假设，系统根据悲观回收和预算反推可接受单价。
- 先用每个尺码的需求减去同类库存，再受门店总容量约束。留仓会单独提示。当前按单批评估，多批次之间不预占容量。
- 用户确认的是当时的输入和依据。修改报价、证据或选店后需重新确认。系统给建议，最终决定由人保存。
- 核心数字由 TypeScript 规则计算。默认使用规则说明，可选模型接口仅用于解释。真实模型联调、ERP 对接、跨店协作审批及采购执行有待后续验证。

更多边界见 [决策引擎与计算规则](docs/03_决策引擎与计算规则.md)。
